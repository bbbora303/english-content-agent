> (롤플레이 B형) 파일을 함께 전달하면 됩니다.
>
> ⚠️ **개정 이력**: 이 문서의 1차 버전은 "한 줄 최대 5개, 줄바꿈 시 세로 공간은 그냥 늘어나도 됨"
> 이라는 가정으로 작성됐었습니다. 이후 사용자가 **실제 콘텐츠 화면 스크린샷 2건**(View 6개는 1줄,
> 8개는 4+4 2줄로 배치되면서도 썸네일 영역 전체 높이가 1줄일 때와 동일하게 유지되는 화면)을
> 제공해서 그 가정이 틀렸음을 확인했습니다. 아래 내용은 그 스크린샷을 근거로 전면 수정한
> 2차 버전입니다.
>
> **📌 이 스크린샷의 출처(중요)**: 사용자에게 확인한 결과, 이 2장은 **기존 개발사가 별도로
> 개발한 콘텐츠 화면**입니다 — 저희가 지금 다루고 있는 `view01.js`/`view01.css`(이 저작 도구가
> 병합 대상으로 삼는 마스터 템플릿)에 **이미 구현되어 있는 기능이 아닐 가능성이 높습니다.**
> 즉 "이미 반영됐는지 확인"이 아니라, **이 스크린샷을 목표 동작(target behavior)으로 삼아
> 새로 구현해달라는 요청**으로 받아주세요.

## 배경 — 핵심 제약: "썸네일 영역의 세로 한계선은 항상 [해석] 버튼 라인과 일치해야 한다"

사용자가 실제 콘텐츠 스크린샷 2장을 제공하며 확인해준 내용:
- **View 6개(우산 분실물 예시)**: 한 줄에 6개가 모두 들어감 — 버튼 높이는 기존과 동일(큼직함).
- **View 8개(옷/모자 예시)**: 4개씩 2줄로 나뉨 — 그런데 **각 줄의 버튼 높이가 눈에 띄게 낮아져서,
  1줄일 때와 2줄일 때의 "썸네일 영역 전체 높이(맨 위~맨 아래)"가 서로 거의 같아 보임**. 즉 줄이
  늘어난다고 영역이 아래로 늘어나는 게 아니라, **줄 수만큼 버튼 높이 자체가 줄어들어 전체 높이가
  고정된 한계선(대사 박스 하단의 [해석] 버튼 라인)을 넘지 않도록 맞춰지는 방식**으로 보입니다.

이 두 데이터 포인트만으로 정확한 임계값(몇 개부터 다음 줄로 넘어가는지, 열을 몇 개씩 나누는지,
버튼 높이가 정확히 몇 px까지 줄어드는지)을 역산하기엔 근거가 부족합니다 — **아래 요청 사항은
저희 쪽 추정이며, 실제 `view01.js`/`view01.css` 코드로 정확한 값을 확인·반영해주시기를
요청드립니다.**

## 요청 사항 (저희 쪽 추정 — 실제 코드로 검증 필요)

1. **한 줄 최대 6개** — 6개까지는 한 줄에 배치(폭은 기존처럼 `(420-(N-1)×gap)/N`로 축소), 7개부터
   다음 줄로 넘어감. (근거: 6개 예시는 1줄, 8개 예시는 2줄이었던 것으로 역산 — 정확히 6개가
   임계값인지, 혹은 7개도 1줄에 들어가는지는 저희도 확실치 않습니다.)
2. **줄 수(rows)에 맞춰 열(columns)을 균등 분배** — `columns = ceil(N / rows)`. 예: N=8, rows=2 →
   columns=4 (4+4로 균등 분할). N=7이라면 rows=2, columns=4 → 4+3으로 분할(마지막 줄은 개수가
   적어도 같은 버튼 폭 유지, 남는 공간은 비움)로 추정했습니다.
3. **전체 세로 높이는 줄 수와 무관하게 고정** — 기존 1줄 기준 높이(버튼 높이 75px)를 "썸네일
   영역의 총 높이 한계"로 보고, 줄이 2개면 `(75 - gap) / 2`, 3개면 `(75 - 2×gap) / 3`처럼 **버튼
   높이 자체를 줄 수만큼 나눠서** 총 높이가 항상 75px(=대사 박스 하단 [해석] 버튼 라인)를 넘지
   않도록 했습니다. 내부 썸네일 이미지 크기도 버튼 높이가 줄어드는 만큼 비례 축소했습니다.

저희 저작 도구 캔버스 미리보기에는 이 추정대로 반영해뒀습니다:

```js
const PANEL_ROW_WIDTH = 420;
const PANEL_ROW_GAP = 6;
const PANEL_MAX_PER_ROW = 6;
const PANEL_TOTAL_HEIGHT = 75; // 줄 수와 무관하게 항상 이 총 높이 안에서 나눠 가짐
const rows = Math.ceil(N / PANEL_MAX_PER_ROW);
const columns = Math.ceil(N / rows);
const btnWidth = (PANEL_ROW_WIDTH - (columns - 1) * PANEL_ROW_GAP) / columns;
const btnHeight = (PANEL_TOTAL_HEIGHT - (rows - 1) * PANEL_ROW_GAP) / rows;
```

## 요청드리는 작업

1. `view01.js`/`view01.css`에 위 추정 로직("N개일 때 줄바꿈 + 높이 고정 축소")을 새로
   구현해주세요. 정확한 임계값(한 줄 최대 개수)과 총 높이 한계값(실제 [해석] 버튼까지의 정확한
   px 거리)은 저희가 가진 CSS 값(메인 이미지 폭 420px, 버튼 높이 75px 등)을 참고하시되, 디자인
   의도에 맞게 조정해서 확정해주시고, **최종 확정된 계산식(열 배분 공식·버튼 높이 공식·정확한
   px 값)을 회신해주세요** — 저희 쪽 캔버스 미리보기도 그 값에 정확히 맞춰 다시 조정하겠습니다.
2. 줄이 2개 이상일 때 대본 영역(`role-play-script`, 좌측 이미지 아래)이나 다른 요소와 겹치지
   않는지 확인 부탁드립니다.
3. View 4개 이하인 기존 콘텐츠(가장 흔한 케이스)는 이전과 동일하게 1줄·기존 버튼 높이로 보여야
   합니다 — 회귀가 없는지 확인 부탁드립니다.

  참고용으로만 적어둡니다).

## 확인 후 처리

정확한 값(임계값·열 배분·높이 계산식)을 회신해주시면, 저작 도구(content-agent) 쪽 캔버스
미리보기 계산식을 그 값에 맞춰 다시 조정하겠습니다. 저작 도구가 내보내는 `rolePlayData` 배열
자체(씬 개수·이미지 파일명)는 이미 올바르므로 그 외 추가로 손댈 코드는 없습니다.
