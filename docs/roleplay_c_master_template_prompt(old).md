# 롤플레이 C형 마스터 템플릿 신규 제작 요청 — 작업 프롬프트

> 이 문서는 **저작 도구(content-agent) 대화**에서 정의한 "롤플레이 C형"에 대해, 그에 대응하는
> 마스터 템플릿을 새로 만들기 위해 **마스터 템플릿 대화**로 넘기는 작업 지시문입니다.
> CLAUDE.md 5-5(저작 도구와 마스터 템플릿은 서로 다른 코드베이스)에 따라 관심사를 분리했습니다.
> 이 문서를 그 대화에 그대로 붙여넣고, **롤플레이 A형의 실제 마스터 템플릿 파일**(view0X.js,
> view0X.css, 그리고 만약 정적 HTML이라면 view0X.html까지)과 아래 첨부 이미지 2종을 함께
> 전달하면 됩니다.

## 진행 방식 (중요)

작업자(사용자)가 **A형 마스터 템플릿 파일을 그대로 복사해서 C형용 새 파일 세트를 만들어 둘
예정**입니다. 마스터 템플릿 담당 에이전트는:
- **A형 원본 파일은 건드리지 마세요** (기존 A형 콘텐츠에 영향이 가면 안 됨).
- 복사된 C형 파일 안의 코드만 아래 요청 내용에 맞게 수정해 주세요.
- 파일명/경로는 사용자가 이미 복사해둔 대로 사용하고, 임의로 새로 만들지 마세요.

## 배경

저작 도구에 롤플레이 C형이라는 새 콘텐츠 유형을 추가했습니다. 사용자가 정의한 C형의 성격은
**"A형에서 표 퀴즈(Table Quiz)만 빠진 구조"**입니다 — 그 외 대사 데이터 구조, 강조 표현(emp
색상), 전체적인 동작·디자인은 A형과 동일하다는 전제입니다.

저작 도구(App.jsx) 쪽은 이미 A형 코드를 그대로 복제해서 C형 캔버스·편집 패널·export 로직을
마련해뒀지만, 이는 어디까지나 "실제 C형 마스터 템플릿이 나올 때까지의 임시 상태"이고, 그
결과물을 실제로 병합할 수 있는 C형 전용 마스터 템플릿은 아직 존재하지 않습니다. 이 문서가 그
신규 제작을 요청하는 문서입니다.

## 0. [가장 먼저 확인해 주세요] A형이 정적 HTML 기반인지, 데이터 기반 동적 렌더링인지

이전에 롤플레이 A형 마스터 템플릿(view01.js)을 확인했을 때, B형의 `renderRolePlay()`처럼
`data.js` → DOM을 동적으로 그려주는 렌더 함수가 A형에는 보이지 않았습니다. 대신 `ii`라는
클래스가 **이미 존재하는 정적 HTML 요소**(`.talk`, `.role-eng-text` 등)를 찾아서 오디오 재생·
빈칸 마스킹 같은 상호작용만 붙이는 구조로 보였습니다. 즉 대사 텍스트 자체가 `data.js`가 아니라
별도의 정적 HTML(예: `view01.html`)에 이미 박혀 있는 구조일 가능성이 있습니다. 다만
`contentData`(data.js)가 실제로 그 HTML에 어떻게 반영되는지(레슨마다 손으로 HTML을 새로
작성하는지, 빌드 단계에서 자동 치환되는지)는 이번에 확인이 안 된 상태입니다.

**요청**: 실제 작업(1~2번)을 시작하기 전에 이것부터 확인해 주세요. 확인 결과에 따라 작업
난이도와 방식이 크게 달라집니다.

- **(a) 정적 HTML 기반이 맞는 경우**: "표 퀴즈 제거"는 CSS/좌표 조정만으로 끝나지 않고, 레슨별
  정적 HTML에서 표 퀴즈 DOM을 제거하고 대사 영역을 넓히는 작업까지 포함되어야 합니다. 이 경우
  **C형 콘텐츠를 만들 때마다 이 HTML을 실제로 어떻게 생성/복제하는지**(수작업인지, 어떤 빌드
  스크립트가 있는지)도 함께 알려주세요 — 저작 도구 쪽에서 export 파이프라인을 그에 맞게 다시
  설계해야 할 수도 있습니다.
- **(b) 실제로는 데이터 기반 동적 렌더링이었던 경우**: 위 관찰이 틀린 것이므로, 렌더 함수에서
  표 퀴즈 관련 분기만 제거하면 되는 훨씬 단순한 작업입니다. 이 경우 몇 번 항목(진짜 렌더 함수
  이름과 위치)인지도 같이 알려주시면 저작 도구 쪽 문서(CLAUDE.md)도 정정하겠습니다.

## 1. 요청 작업 — 표 퀴즈 제거 + 대사 영역 레이아웃 조정

- A형 화면에서 표 퀴즈 영역(DOM + 관련 CSS)을 제거합니다.
- 대사 스크립트 영역(A형 기준 `left: 40, top: 256, width: 660, height: 340` 부근)을, 표 퀴즈가
  있던 공간까지 포함해서 넓혀주세요. 정확한 목표 좌표/크기는 아래 첨부한 **콘텐츠 레이아웃
  이미지**(표 퀴즈 없는 최종 완성 화면 목업)를 기준으로 맞춰주세요.
- 그 외 요소는 **전부 A형과 동일하게 유지**합니다: 상단 헤더(뱃지/발문), "How to play" 버튼,
  하단 "해석" 버튼, 대사 텍스트 렌더링 방식, 강조 표현(`emp col-0/1/2`) 색상, 한글 번역 배치
  로직(실측 기반이라면 그 로직 그대로), 빈칸 마스킹/오디오 상호작용 전부 A형 그대로 가져갑니다.
- 표 퀴즈 관련 상호작용(정답 입력, 채점 등) 로직이 있다면 함께 제거해 주세요.

## 2. 데이터 스키마는 A형과 동일하게 유지

저작 도구가 내보내는 C형 데이터는 지금은 A형과 완전히 같은 구조입니다 (`dialogues` 배열,
`speaker`/`sentence`/`kor`/`audio_id` 계열 필드 — 실제 export 시에는 A형과 동일하게
`role`/`text[]`/`translation[]`/`audio[]`류로 변환됩니다). **`tableQuiz` 필드는 아예 없다고
가정하고 무시**하시면 됩니다. (0번 확인 결과 데이터 흐름 자체가 다르다고 밝혀지면 이 항목도
다시 논의합니다.)

## 3. 첨부 자료

- **교과서 원본 이미지(파일명: 교과서_(C형) THINK AND TALK - 2)**: C형으로 판정되어야 할 실제 교과서 지면 (참고용 — 문구·구성 이해)
- **콘텐츠 레이아웃 이미지(파일명: 콘텐츠 레이아웃_(C형) THINK AND TALK - 2)**: 표 퀴즈 없이 병합 추출되어야 할 목표 화면 목업 (좌표/크기 기준으로 삼을 실제 타깃)
