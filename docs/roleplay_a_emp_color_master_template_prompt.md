# 롤플레이 A형 마스터 템플릿 — 강조 표현(emp 색상) 지원 확인/수정 요청 — 작업 프롬프트

> 이 문서는 **저작 도구(content-agent) 대화**에서 롤플레이 A형 캔버스 편집 UX를 고도화한 뒤, 그
> 결과가 실제 마스터 템플릿에서도 동작하는지 확인하기 위해 **마스터 템플릿 대화**로 넘기는 작업
> 지시문입니다. 저작 도구(App.jsx)와 마스터 템플릿(view0X.js/css)은 서로 다른 코드베이스이자 다른
> 관심사라 이 프로젝트에서는 관심사를 분리해서 다룹니다. 이 문서를 그 대화에 그대로 붙여넣고,
> **롤플레이 A형을 렌더링하는 실제 마스터 템플릿 파일**(JS + CSS)을 함께 전달하면 됩니다.

## 배경

저작 도구의 롤플레이 A형 편집 캔버스에 새 기능을 추가했습니다: 사용자가 영어 대사 텍스트 중
강조하고 싶은 부분을 마우스로 선택한 뒤, 빨강/파랑/분홍 색상 버튼을 누르면 그 부분이 자동으로
`<span class='emp col-N'>...</span>`로 감싸지는 UI입니다(`col-0`=빨강, `col-1`=파랑, `col-2`=분홍).

이 기능은 **롤플레이 B형에서 먼저 검증**을 마쳤습니다 — B형의 실제 마스터 템플릿(`view01.js`/
`view01.css`)을 확인한 결과, `.emp.col-0{color:#b42c13}`, `.emp.col-1{color:#018f9e}`,
`.emp.col-2{color:#e0629d}`가 이미 CSS에 정의되어 있었고, 화면에도 정상적으로 반영됐습니다.

**문제는 A형입니다.** A형은 B형과 export 데이터 구조 자체가 다릅니다 — B형은 최상위 변수
`rolePlayData`(배열, 씬 여러 개)를 쓰고 이건 `view01.js`가 명확히 읽고 있는 걸 확인했지만, A형은
최상위 변수 `contentData`(단일 객체, `pageInfo`/`howToPlay`/`rolePlay.dialogues`/`tableQuiz`
구조)를 씁니다. `view01.js`에는 `contentData`나 `pageInfo`, `howToPlay`라는 이름이 전혀 등장하지
않았습니다 — 즉 **A형은 B형과 다른 파일이 렌더링하고 있는 것으로 보이는데, 그 파일을 아직
받아본 적이 없습니다.** 그래서 A형 캔버스에 추가한 파랑/분홍 강조가 실제 병합 결과에서도
보일지 확인이 안 된 상태입니다(빨강만 예전부터 실사용 검증돼 있었음, 아래 3번 참고).

## 1. 어떤 파일이 롤플레이 A형을 렌더링하는지부터 확인 필요

먼저 아래 특징으로 실제 롤플레이 A형 렌더링 파일(JS)을 찾아 알려주세요:
- 최상위 변수명 `contentData` (또는 이와 유사한, `pageInfo`/`howToPlay`/`rolePlay`/`tableQuiz`
  키를 담은 객체)를 읽는 코드가 있는 파일.
- 표 퀴즈(Table Quiz) 렌더링 로직이 있는 파일 — A형은 대화문 옆/아래에 표 형태 퀴즈가 함께
  나옵니다(B형에는 표 퀴즈가 없음).
- `view01.js`와 같은 파일일 수도 있고(같은 페이지 안에 A형 조건 분기가 있을 수도 있음), 다른
  번호의 `view0X.js`(예: `view02.js`)일 수도 있습니다 — 실제로 어떤 파일인지 확인해서
  파일명을 알려주세요.

## 2. 저작 도구가 실제로 내보내는 A형 데이터 구조

`js/data.js`에 아래 형태로 씁니다 (최상위 변수명 `contentData`):

```js
const contentData = {
  pageInfo: {
    hiddenText: "친구의 고민에 공감을 표현하고 조언한 후, 표를 채워 봅시다. 롤플레이 활동이 어려울 경우, 선생님께 도움을 요청해 보세요.",
    title: { head: "B", text: "Talk and Complete", color: "4" },
    instruction: "친구의 고민에 공감을 표현하고 조언한 후, 표를 채워 봅시다."
  },
  howToPlay: [
    { step: 1, tail: "left", lines: ["버튼을 눌러 예시 대화를", "확인하고 이야기해 보세요."] },
    { step: 2, tail: "top", lines: ["역할을 선택해 보세요."] },
    { step: 3, tail: "bottom", lines: ["내가 맡은 역할의 대사를", "가리고 말해 보세요."] },
    { step: 4, tail: "top", lines: ["예시 대화를 참고하여 친구들과 대화한 후,", "표에 알맞은 내용을 써 보세요."] }
  ],
  rolePlay: {
    toggleBtn: { ariaLabel: "클릭 시 대화창 바꾸기" },
    dialogues: [
      {
        speaker: "A",
        lines: [
          {
            hasBlank: false,
            audio: "L3_001_CommB_eg_01",
            // 👇 이번에 바뀐 부분 — 아래 3번 참고
            eng: "I <span class='emp col-1'>usually play basketball</span> with my friends.",
            kor: "나는 보통 친구들과 농구를 해."
          }
        ]
      }
    ]
  },
  tableQuiz: {
    headers: [{ text: "Name", audioId: "" }, { text: "Activity", audioId: "" }],
    staticRow: [{ text: "Minho", audioId: "" }, { text: "playing basketball", audioId: "" }],
    rowCount: 3,
    answers: []
  }
};
```

`hasBlank: true`인 줄에는 `muteTargets`(숫자 배열, 예: `[0]`)가 추가로 붙습니다. 이건 **오디오
파일을 몇 번째 순서에서 묵음 처리할지**를 나타내는 것으로 저희가 이해하고 있고, 이번 강조 색상
작업과는 무관한 별개 기능입니다(3번 참고) — 그대로 유지하시면 됩니다.

## 3. [핵심 확인 요청] `eng` 필드가 이제 raw HTML을 포함할 수 있습니다

**이전에는** `eng` 필드에 사용자가 직접 타이핑한 `[대괄호]` 텍스트(예: `"I enjoy [playing
basketball]."`)가 그대로 문자열로 들어갔습니다. 저작 도구 캔버스에서만 이 대괄호를 자동으로
빨간색 span으로 바꿔서 미리보기로 보여줬을 뿐, **실제로 ZIP에 내보내는 값은 대괄호가 그대로 남은
문자열**이었습니다. (즉 여태까지는 대괄호가 실제 병합 결과에서 어떻게 보이는지 저희 쪽에서
확인할 방법이 없었습니다 — 마스터 템플릿이 대괄호를 자체적으로 파싱해서 강조 처리를 하고
있었는지, 아니면 그냥 대괄호가 그대로 노출되고 있었는지도 불확실합니다.)

**이번에 바뀐 것**: 대괄호 방식을 없애고, 사용자가 강조할 부분을 선택하면 저작 도구가 직접
`eng` 필드 문자열 안에 `<span class='emp col-N'>...</span>` HTML을 끼워 넣도록 바꿨습니다(B형과
동일한 방식). 즉 이제 `eng` 필드에는 **일반 텍스트 안에 HTML 태그가 섞여 있는 문자열**이 들어갈
수 있습니다.

**확인해주셔야 하는 것**:
1. 실제 마스터 템플릿이 `eng` 값을 DOM에 넣을 때 `innerHTML`(또는 이에 상응하는, HTML 태그를
   실제 마크업으로 해석하는 방식)을 쓰는지, 아니면 `textContent`(HTML 태그가 그대로 글자로
   노출되는 방식)를 쓰는지 확인해주세요.
   - `innerHTML` 방식이면 → 저희가 넣은 `<span class='emp col-N'>` 태그가 그대로 강조 표시로
     렌더링될 것이므로 **추가 조치 불필요**합니다.
   - `textContent` 방식이면 → 화면에 `<span class='emp...` 텍스트가 그대로 노출되는 문제가
     생기므로, **innerHTML 방식으로 바꿔주시거나**, 저희 쪽에서 다른 방식(예: 별도 필드로
     강조 구간의 시작/끝 인덱스와 색상을 전달)으로 바꿔야 합니다 — 어느 쪽이 나을지 의견
     주시면 저희 쪽(App.jsx)도 그에 맞춰 조정하겠습니다.
2. 위 1번이 `innerHTML` 방식이라면, CSS에 `.emp.col-0`, `.emp.col-1`, `.emp.col-2` 클래스가 이미
   정의되어 있는지 확인해주세요. 저희가 기대하는 색상은 롤플레이 B형(view01.css)과 동일하게
   맞추고 싶습니다 — **빨강 `col-0` = `#b42c13`, 파랑 `col-1` = `#018f9e`, 분홍 `col-2` =
   `#e0629d`**. 이미 있다면 그 색상 값을 알려주세요(저희 기대값과 다르면 저희 쪽 색상 팔레트를
   그 값에 맞춰 수정하겠습니다). 없다면 새로 추가해주시고, 색상 값도 위와 동일하게(또는 이미
   같은 프로젝트 내 다른 화면에서 쓰는 값이 있다면 그 값으로 통일해서) 정의해주세요.
3. `hasBlank`/`muteTargets`(오디오 묵음) 기능과 `emp` 강조 색상은 서로 무관한 기능이라는 점을
   확인 부탁드립니다 — 혹시 A형 마스터 템플릿에서 예전에 "빈칸으로 표시될 단어는 항상 빨간색
   강조로도 함께 표시된다" 같은 연동 로직이 있었다면 알려주세요. 저희 쪽 저작 도구에서는 이번에
   두 기능을 완전히 분리했습니다(체크박스는 오디오 묵음 여부만 담당, 강조 색상은 텍스트 선택 +
   색상 버튼으로 별도 지정).

## 참고 — B형(view01.js/css)에서 이미 확인된 사실 (비교용)

B형은 위 1번·2번 질문에 대해 이미 "가능함"으로 확인됐습니다 — `view01.js`의 `renderRolePlay()`가
문장을 `<span>` DOM 요소로 만들 때 `span.innerHTML = splitLine`(HTML 태그 해석 방식)을 쓰고
있었고, `view01.css`에 `.emp.col-0/1/2`가 이미 위와 동일한 색상으로 정의돼 있었습니다. A형이
B형과 같은 파일(또는 같은 디자인 시스템을 공유하는 다른 파일)이라면 이미 지원되고 있을 가능성이
높습니다 — 그렇다면 이 문서에 대한 답변은 "확인 완료, 추가 조치 없음"이 될 수도 있습니다.

## 확인 후 처리

이 답변들을 받으면, 저작 도구(content-agent) 쪽에서:
- 1번이 `textContent` 방식이면 → 강조 표현 전달 방식을 다시 설계(App.jsx 수정)
- 2번의 실제 색상 값이 저희 기대값과 다르면 → `EMP_COLORS` 상수(`src/App.jsx`) 색상 값을 실제
  값에 맞춰 수정
- 3번에서 예전 연동 로직이 있었다고 하면 → hasBlank 체크박스와 강조 색상의 관계를 다시 검토
