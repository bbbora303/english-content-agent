# 롤플레이 C형 마스터 템플릿 신규 제작 요청 — 작업 프롬프트

> 이 문서는 **저작 도구(content-agent) 대화**에서 정의한 "롤플레이 C형"에 대해, 그에 대응하는
> 마스터 템플릿을 새로 만들기 위해 **마스터 템플릿 대화**로 넘기는 작업 지시문입니다.
> CLAUDE.md 5-5(저작 도구와 마스터 템플릿은 서로 다른 코드베이스)에 따라 관심사를 분리했습니다.
>
> 이 문서를 그 대화에 그대로 붙여넣고, **롤플레이 A형의 실제 마스터 템플릿 파일**(view0X.js,
> view0X.css, 그리고 만약 정적 HTML이라면 view0X.html까지)과 아래 첨부 이미지 2종을 함께
> 전달하면 됩니다.

## 배경

저작 도구에 롤플레이 C형이라는 새 콘텐츠 유형을 추가했습니다. C형 교과서 지면은 공통 도입
대사 하나(A: Have you heard about the new movie...)에서 초록/빨강 화살표로 **두 갈래(Yes/No)로
갈리는 분기 대화**입니다. 표 퀴즈는 없습니다.

목표 레이아웃(콘텐츠 레이아웃 이미지)을 보면, 표 퀴즈가 있던 자리는 대사 영역 확장이 아니라
**하단 페이지네이션**(◀ 페이지번호 ○ ▶)으로 대체되어 있습니다. 즉 한 페이지(=한 갈래)의 대사
4줄이 A형과 동일한 대사 박스 스타일로 표시되고, 사용자가 화살표를 눌러 다른 갈래(페이지)로
전환하는 구조입니다. 공통 도입 대사("A: Have you heard...")는 각 페이지 맨 앞에 반복해서
포함됩니다(교과서 지면에서 화살표로 갈라지는 지점 자체가 도입 대사 바로 다음이므로, 각 갈래를
완결된 대화로 재생하려면 도입 대사부터 다시 보여줘야 합니다).

저작 도구(App.jsx) 쪽은 현재 A형 코드를 문자 그대로 복제해서 C형 캔버스·편집 패널·export
로직을 마련해뒀지만(주석에 "A형 로직을 그대로 복제"라고 명시돼 있음), 이는 어디까지나 "실제
C형 마스터 템플릿이 나올 때까지의 임시 상태"이고 지금은:
- 대사가 여전히 단일 순차 배열(`dialogues`)로만 추출·저장됩니다 — 페이지/갈래 구분이 없습니다.
- 표 퀴즈 UI가 아직 그대로 남아 있습니다(좌표 `left:710` 부근).
- 페이지네이션 UI/상태가 전혀 없습니다.

이 문서에서 제안하는 데이터 구조와 마스터 템플릿의 실제 렌더 방식이 서로 맞아야 하므로, 아래
0번 확인 결과와 페이지네이션 구현 방식에 따라 저작 도구 쪽 데이터 스키마도 함께 확정할
예정입니다(2번 항목 참고 — 확정이 아니라 제안입니다).

## 0. [가장 먼저 확인해 주세요] A형이 정적 HTML 기반인지, 데이터 기반 동적 렌더링인지

이전에 롤플레이 A형 마스터 템플릿(view01.js)을 확인했을 때, B형의 `renderRolePlay()`처럼
`data.js` → DOM을 동적으로 그려주는 렌더 함수가 A형에는 보이지 않았습니다. 대신 `ii`라는
클래스가 **이미 존재하는 정적 HTML 요소**(`.talk`, `.role-eng-text` 등)를 찾아서 오디오 재생·
빈칸 마스킹 같은 상호작용만 붙이는 구조로 보였습니다.

**이 질문은 특히 중요합니다.** 페이지네이션은 "같은 자리에 다른 대사 세트를
갈아끼우는" 동적 상태 전환이 필요한 기능이라, A형이 정말 정적 HTML이라면 페이지마다 별도
HTML 블록을 미리 만들어 두고 JS로 보이기/숨기기만 전환하는 방식이 될지, 아니면 이번 기회에
C형만 데이터 기반 렌더링으로 새로 작성할지 결정이 필요합니다.

**요청**: 실제 작업(1~2번)을 시작하기 전에 이것부터 확인해 주세요.

- **(a) 정적 HTML 기반이 맞는 경우**: 표 퀴즈 DOM 제거 + 대사 영역 확장에 더해, **갈래(페이지)
  개수만큼 대사 블록 HTML을 미리 준비해두고 페이지 전환 시 표시/숨김을 토글하는 구조**가
  필요합니다. 이 경우 C형 콘텐츠를 만들 때마다 이 HTML을 실제로 어떻게 생성/복제하는지(수작업인지,
  빌드 스크립트가 있는지), 그리고 갈래 개수가 지면마다 다를 수 있는데(교과서 표본이 아직 1장뿐이라
  2갈래 고정인지 3갈래 이상도 있는지 불확실) 그 경우 HTML을 몇 개까지 미리 준비해두는 게 안전할지도
  같이 알려주세요.
- **(b) 실제로는 데이터 기반 동적 렌더링이었던 경우**: 렌더 함수에 페이지 상태(현재 페이지 인덱스)를
  추가하고, 표 퀴즈 렌더 분기를 페이지네이션 렌더 분기로 바꾸면 되는 상대적으로 단순한 작업입니다.
  이 경우 몇 번 항목(진짜 렌더 함수 이름과 위치)인지도 같이 알려주시면 저작 도구 쪽 문서(CLAUDE.md)도
  정정하겠습니다.

## 1. 요청 작업 — 표 퀴즈 제거 + 분기 페이지네이션 추가

- A형 화면에서 표 퀴즈 영역(DOM + 관련 CSS)을 제거합니다. 관련 상호작용(정답 입력, 채점 등)
  로직이 있다면 함께 제거해 주세요.
- 대사 스크립트 영역(A형 기준 `left: 40, top: 256, width: 660, height: 340` 부근)은 표 퀴즈가
  있던 공간까지 넓히지 않고, **첨부한 콘텐츠 레이아웃 이미지의 대사 박스 크기·위치를 그대로
  따릅니다**(이미지 상 대사 영역은 A형보다 폭이 넓어졌지만 우측 표 퀴즈 자리 전체를 차지하진
  않고, 그 아래/옆에 페이지네이션 공간이 남습니다 — 정확한 좌표는 이미지 실측 기준으로
  맞춰주세요).
- 대사 박스 우측 상단의 `e.g.` 배지, 상단 헤더(뱃지/발문), `How to play` 버튼, `Role-play`
  A/B/A&B 토글, `시작하기`/`대사 가리기` 버튼, 진행 바, 하단 `해석` 버튼은 **전부 A형과 동일하게
  유지**합니다. 대사 텍스트 렌더링 방식, 강조 표현(`emp col-0/1/2`) 색상, 한글 번역 배치 로직
  (실측 기반이라면 그 로직 그대로), 빈칸 마스킹/오디오 상호작용도 A형 그대로 가져갑니다.
- **신규: 하단에 페이지네이션 컴포넌트를 추가합니다** — 좌우 화살표(◀ ▶)와 페이지 도트
  인디케이터(현재 페이지는 채워진 원, 나머지는 빈 원). 첨부 레이아웃 이미지에서 정확한 디자인
  (색상, 크기, 위치)을 확인해 주세요. 페이지 전환 시:
  - 대사 박스 내용이 해당 페이지의 대사 세트로 교체됩니다.
  - `시작하기`/`대사 가리기`/오디오 재생 상태가 페이지 전환 시 초기화되는지, 아니면 페이지별로
    독립적으로 유지되는지는 아직 정해지지 않았습니다 — 구현하시면서 자연스러운 기본값(예: 페이지
    전환 시 초기화)으로 진행하시고, 어느 쪽으로 하셨는지 알려주시면 저작 도구 쪽 문서에
    반영하겠습니다.
  - 갈래(페이지) 개수는 지면마다 다를 수 있다는 전제로, 페이지 수를 하드코딩하지 말고 데이터
    배열 길이에 따라 동적으로 도트 개수가 정해지도록 구현해 주세요.

## 2. 데이터 스키마 제안 (확정 아님, 협의 필요)

"A형과 완전히 동일한 `dialogues` 단일 배열"로는 부족합니다. 페이지네이션을 반영하려면 대사가
**갈래(페이지) 단위로 묶여야** 합니다. 저작 도구 쪽에서 아래와 같은 구조를 제안합니다. 각
페이지는 공통 도입 대사를 포함해 완결된 대화 시퀀스이므로(교과서 지면에서 화살표 분기 지점 자체가
도입 대사 다음이라, 페이지 전환 시 앞부분을 다시 보여줘야 자연스럽습니다), 페이지 간에 상태를
공유할 필요 없이 각 페이지가 독립적인 대사 배열을 갖습니다.

```js
rolePlay: {
  toggleBtn: { ariaLabel: "클릭 시 대화창 바꾸기" },
  pages: [
    {
      pageId: 0,
      // A형과 동일한 turn 배열 구조. 공통 도입 대사(Have you heard...)가 맨 앞에 포함됨.
      dialogues: [
        { speaker: "A", lines: [{ hasBlank: false, audio: "", eng: "Have you heard about the new movie A Stranger from Mars?", kor: "..." }] },
        { speaker: "B", lines: [{ hasBlank: false, audio: "", eng: "Yes, I have. I heard it has a great story.", kor: "..." }] },
        { speaker: "A", lines: [{ hasBlank: false, audio: "", eng: "Let's watch it together.", kor: "..." }] },
        { speaker: "B", lines: [{ hasBlank: false, audio: "", eng: "Sounds good! I'm looking forward to it.", kor: "..." }] }
      ]
    },
    {
      pageId: 1,
      dialogues: [
        { speaker: "A", lines: [{ hasBlank: false, audio: "", eng: "Have you heard about the new movie A Stranger from Mars?", kor: "..." }] },
        { speaker: "B", lines: [{ hasBlank: false, audio: "", eng: "No, I haven't.", kor: "..." }] },
        { speaker: "A", lines: [{ hasBlank: false, audio: "", eng: "I heard it has a great story. I'm looking forward to it.", kor: "..." }] },
        { speaker: "B", lines: [{ hasBlank: false, audio: "", eng: "Sounds good! Let's watch it together.", kor: "..." }] }
      ]
    }
  ]
}
```

- `tableQuiz` 필드는 아예 없다고 가정하고 무시하시면 됩니다.
- 각 `dialogues` 배열 안의 turn/line 구조(`speaker`, `lines[].eng/kor/audio/hasBlank` 등)는
  A형과 완전히 동일합니다 — 새로 배울 구조가 아니라, 그 배열을 감싸는 `pages` 껍데기만
  새로 생겼다고 보시면 됩니다.
- 페이지 개수(`pages.length`)만큼 페이지네이션 도트를 그리고, 클릭/화살표 이벤트로 현재 페이지
  인덱스를 바꿔 해당 페이지의 `dialogues`를 렌더링하면 됩니다.
- **이 구조는 확정이 아니라 제안입니다.** 0번 확인 결과(정적 HTML vs 동적 렌더링) 및 실제 구현
  방식에 따라 더 적합한 구조가 있다면 알려주세요 — 저작 도구 쪽 export 로직을 그에 맞춰
  조정하겠습니다.

## 3. 첨부 자료

- **교과서 원본 이미지(파일명: 교과서_(C형) THINK AND TALK - 2)**: C형으로 판정되어야 할 실제
  교과서 지면. 공통 도입 대사(A) → 초록 화살표(Yes 갈래) / 빨강 화살표(No 갈래) 분기 구조를
  보여주는 참고 자료입니다.
- **콘텐츠 레이아웃 이미지(파일명: 콘텐츠 레이아웃_(C형) THINK AND TALK - 2)**: 표 퀴즈 없이
  병합 추출되어야 할 목표 화면 목업. 대사 박스 좌표/크기와 하단 페이지네이션 디자인 모두 이
  이미지를 실측 기준으로 삼아 주세요. (이미지상 페이지 1이 초록/Yes 갈래로 채워져 있고, 페이지
  2는 아직 비어 있는 도트로만 표시돼 있습니다 — 페이지 2 내용은 교과서 원본 이미지의 빨강 갈래를
  참고하시면 됩니다.)

## 결과물 — 아래 항목을 빠짐없이 정리해서 알려주세요

파일만 수정해서 돌려주시면 안 되고, 답변에 아래를 전부 포함해 주세요(저작 도구 쪽에서 App.jsx를
바로 고칠 수 있어야 합니다):

1. 0번 확인 결과: 정적 HTML 기반인지 데이터 기반 동적 렌더링인지, 그리고 정적이라면 레슨별
   HTML을 어떻게 생성/복제하는지(수작업/빌드 스크립트 등 구체적으로).
2. 2번에서 제안한 `pages` 구조를 그대로 썼는지, 다르게 구현했다면 실제 사용한 데이터 구조(키
   이름·중첩까지 정확히).
3. 실제 적용한 대사 영역·페이지네이션 좌표/크기값(픽셀 단위).
4. 페이지 전환 시 오디오 재생/대사 가리기 상태를 초기화했는지, 유지했는지.
5. 페이지 개수를 몇 개까지 고정/가변으로 처리했는지(데이터 배열 길이 기반인지, 하드코딩인지).
6. 수정된 파일 목록과 경로.

## 확인 후 처리

이 답변과 수정된 파일을 받으면, 저작 도구(content-agent) 쪽에서:
- 0번 확인 결과에 따라 export 파이프라인(정적 HTML 생성 필요 여부)을 조정
- 2번에서 제안한 `pages` 스키마가 실제 구현과 다르면 그에 맞춰 App.jsx의 데이터 구조·편집
  패널(페이지별 대사 편집 UI)을 다시 설계
- 대사 영역·페이지네이션 좌표/크기가 실제 템플릿과 다르면 `src/App.jsx`의 C형 캔버스 좌표를
  그에 맞게 수정
- 관리자 모드에 C형 전용 마스터 템플릿 ZIP을 등록해서 실제 병합 추출 테스트
